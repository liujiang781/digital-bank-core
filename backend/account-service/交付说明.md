# S2 账户服务交付说明

本次代码基于小组仓库提交 `f331eabb2d82d10a15fd23d809af096f0a55a5e4`，实现 S2 账户生命周期、余额查询、存款受理与结果确认、取款、本行转账及失败释放。

交付包严格按组长划定的 S2 范围组织，所有文件都在 `backend/account-service/` 下：源码在 `src/main/java/`，配置和 SQL 交接材料在 `src/main/resources/`，测试在 `src/test/`，接口交接、实现说明、AI 记录和测试结果在 `docs/`。父 POM、common、其他服务、deploy 和 frontend 不在本次交付范围。

```text
backend/account-service/
├── pom.xml
├── README.md
├── 交付说明.md
├── docs/
│   ├── S2-S3接口交接说明.md
│   ├── S2-账户与记账实现说明.md
│   ├── S2-AI使用记录.md
│   ├── S2-测试结果.json
│   └── S2-HTTP启动验证.json
└── src/
    ├── main/java/com/digitalbank/account/
    ├── main/resources/
    └── test/
```

使用方式：

1. 在小组完整仓库中合入包内相同目录的文件；JDK 使用 21，父 POM 和 common 沿用组长骨架。
2. 将 `src/main/resources/db/s2-incremental.sql` 交给 S4，由其纳入 `deploy` 并在同一 MySQL 主库执行。已有数据只执行增量。
3. 按 [账户服务说明](README.md) 配置数据库和内部令牌，并在 backend 执行 `./mvnw.cmd -pl account-service -am clean install`。
4. S1 向账户接口接入服务器 Principal；S3 按 [交接执行版](docs/S2-S3接口交接说明.md) 调用内部端点。

验证结果：H2 与真实 MySQL 各 47 项自动化测试通过，打包 JAR 的 11 项 HTTP/数据库检查通过。S1/S3/S5 的真实服务端到端联调由小组接入后进行。
