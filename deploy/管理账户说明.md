# 管理账户创建说明

后台菜单（运营管理、风控管理）只对有 `OPERATIONS` 或 `RISK` 角色的账号显示。
普通客户登录后看不到后台入口，直接输网址也会被路由守卫挡回账户页。

前端的角色来自**服务端登录响应**里的 `customer.roles`，前端只做展示控制。
真正的权限校验在服务端，前端传的角色不可信。

## 演示管理账号（已创建）

| 账号 | 密码 | 角色 | 账户范围 | 可见菜单 |
|---|---|---|---|---|
| `OPS-ADMIN` | `admin123` | `OPERATIONS` | ACC-0001、ACC-0002 | 仅运营管理 |
| `OPS-RISK` | `admin123` | `RISK` | ACC-0001、ACC-0002 | 仅风险控制（含全部写操作） |

前端按账号精确隔离后台模块：运营管理只给 OPS-ADMIN，风险控制只给 OPS-RISK。
其他账号登录后看不到后台入口，直接输后台网址也会被引擎挡回账户页。

一个账号只能有一个角色（数据库主键是 identity_id）。
要同时做运营和风控操作，请分别用两个账号登录不同标签页。

## 创建新的管理账户

分三步。全部在 MySQL 里操作。

### 第一步：准备客户和凭据

如果客户已存在，跳过。否则参考 `deploy/sql/init-data.sql` 插入：

```sql
-- 客户记录
INSERT INTO customer (customer_id, identity_id, name, real_name_status, status)
VALUES ('CUS-OP01', 'OPS-USER01', '运营用户', 'VERIFIED', 'NORMAL');

-- 登录凭据（密码哈希见下一步生成）
INSERT INTO credential (customer_id, username, password_hash, credential_type, status)
VALUES ('CUS-OP01', 'ops01', '<BCrypt哈希>', 'USERNAME', 'NORMAL');
```

登录用的是 `identity_id`（如 `OPS-USER01`），不是 username。

### 第二步：生成密码哈希

项目用 BCrypt（strength 12）。用 Java 生成：

```java
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
System.out.println(new BCryptPasswordEncoder(12).encode("你的密码"));
```

也可以用 deployment 目录的脚本：`deploy/set-demo-password.sh`（Linux/Mac）。

### 第三步：插入授权记录和账户范围

```sql
-- 角色：只允许 OPERATIONS 或 RISK（表约束 chk_staff_role）
INSERT INTO staff_authorization (identity_id, role_id, version)
VALUES ('OPS-USER01', 'OPERATIONS', 1);

-- 账户范围：必须显式授权，空范围会被服务端 403 拒绝
INSERT INTO staff_account_scope (identity_id, account_id)
VALUES ('OPS-USER01', 'ACC-0001'), ('OPS-USER01', 'ACC-0002');
```

`accountScope` 是数据权限范围，不是全局权限。空范围表示「看不到任何账户」，
不是「看全部账户」。要查看全行数据，就把所有账户号都插进去。

## 两种角色的区别

| 角色 | 对应演示账号 | 可见菜单 | 可用功能 |
|---|---|---|---|
| `OPERATIONS` | OPS-ADMIN | 仅运营管理 | 客户列表、冻结解冻、交易核对与恢复。角色授权接口不可用（见下方说明） |
| `RISK` | OPS-RISK | 仅风险控制 | 规则配置、名单维护、审批、告警处置、风险记录 |

后端 `RiskAccess` 的权限划分：

- 查询（规则列表、风险记录）：`RISK`、`OPERATIONS`、`AUDIT` 都可以，需要非空账户范围。
- 写操作（规则/名单变更、审批、告警处置）：只接受 `RISK`，且需要非空账户范围。

前端在后端校验之外，进一步按演示账号隔离模块：OPS-ADMIN 只看到运营管理，OPS-RISK 只看到风险控制。
这是展示层的约束，服务端仍会独立校验每个接口的权限。
一个账号在 `staff_authorization` 里只能有一个角色（主键是 identity_id）。

## 一个待后端确认的矛盾：角色授权接口

运营管理页有"角色授权"入口，但点击会报"仅系统管理员可以管理角色和授权范围"。
原因是后端 `RoleManagementService.requireAdmin()` 要求 `roles` 恰好等于 `{ADMIN}`。

但数据库约束 `chk_staff_role` 只允许 `OPERATIONS` 和 `RISK`，不允许插入 `ADMIN`。
所以目前没有任何账号能通过业务接口做角色授权。

创建管理账号只能直接用 SQL 操作 `staff_authorization` 和 `staff_account_scope`（见上方步骤）。
要让"角色授权"按钮可用，需要后端同时修改两处：放宽接口角色要求，或让数据库允许 ADMIN 角色。这个问题已反馈，未擅自改动后端和数据库。

## 权限校验链路

1. 登录时 `StaffAuthorizationService` 从 `staff_authorization` 和 `staff_account_scope` 读角色与范围，写进服务端会话。
2. 登录响应返回 `customer.roles`，前端据此显示菜单。
3. 每次请求服务端重新查授权比对，改权限或撤销会立即失效。
4. 业务层从 `getUserPrincipal()` 读角色，不读前端传的任何角色参数。

因此前端改不了权限。要调整账号权限，只改数据库授权表即可，下次请求立即生效。

## 排错

**登录后看不到后台菜单**：查 `staff_authorization` 有没有这个 identity_id 的记录，角色拼写是否正确。

**能看到菜单但接口 403**：查 `staff_account_scope`，空范围会被服务端拒绝。

**登录报 503「授权存储暂时不可用」**：`staff_authorization` 表不存在，执行 `deploy/sql/s1-incremental.sql`。

**登录返回 roles 为空**：授权记录的 identity_id 和登录用的身份标识不一致。登录用 `identity_id` 字段，不是 username。
