# 一键启动 / 停止（Windows）

本目录提供三个文件，用于一键拉起前端页面所需的全部服务：

| 文件 | 用途 |
|---|---|
| `一键启动.bat` | 双击启动全部服务（MySQL + 5 个后端服务 + 前端 Vite） |
| `一键停止.bat` | 双击停止全部服务 |
| `start-all.ps1` | 启动脚本本体（供 .bat 调用） |
| `stop-all.ps1` | 停止脚本本体（供 .bat 调用） |

## 使用方法

**直接双击 `一键启动.bat`**。脚本会：

1. 检查 JDK 21 和 5 个服务 JAR 是否存在。
2. 启动 MySQL80 服务（如果没运行）。
3. 停掉 8081/8082/8083/8084/8090/5173 端口上的旧进程。
4. 按正确端口和环境变量启动 5 个后端服务（**无窗口弹出**，日志写入 `logs/`）。
5. 等待所有后端日志出现 `Started ...Application` 标记（最多 60 秒）。
6. 启动前端 Vite 开发服务器（同样无窗口）。

启动器窗口会一直显示进度，最后停在"完成"提示；关掉这个窗口不影响后台服务。

启动完成后浏览器访问：**http://localhost:5173**
演示账号：**UID-000001 / demo123**

停止时双击 `一键停止.bat`。

## 前置条件

- JDK 21：`C:\Program Files\Microsoft\jdk-21.0.7.6-hotspot`
- 后端已构建：在 `backend/` 执行 `mvnw.cmd -s .mvn/central-settings.xml clean install`
- 前端依赖已安装：在 `frontend/` 执行 `npm install`
- Node/npm：本机 Node 在 `C:\Users\26043\.workbuddy\binaries\node\versions\22.22.2-6`。
  这个目录不在系统 PATH 里，所以脚本启动前端时会显式补 PATH（见 `start-all.ps1` 的 `$NodeBin`）。
  换机器时把 `$NodeBin` 改成实际的 Node bin 目录。
- 数据库已初始化：`sql/schema.sql` → S2/S3 增量 → `sql/init-data.sql`

### 数据库增量脚本必须执行

user-service 用 MySQL 凭据模式，登录时要查 `staff_authorization` 表。
如果只建了基础 schema 而没跑增量脚本，登录会报 503「授权存储暂时不可用」，
个人资料接口会报 404「请求路径、方法或媒体类型不支持」。

首次部署或升级代码后，按顺序执行五个增量脚本：

```
deploy/sql/s1-incremental.sql                                       （用户与授权表）
backend/account-service/src/main/resources/db/s2-incremental.sql      （账户命令与预留）
backend/transaction-service/src/main/resources/db/s3-incremental.sql  （模拟渠道与人工操作；含 audit_log 约束调整）
backend/risk-service/src/main/resources/db/s3-risk-incremental.sql    （告警、审批单、风险名单）
deploy/sql/s2-requirement-gaps-incremental.sql                       （risk_freeze_release 风控解除结论表）
```

前四个是历史脚本，本机库已经执行过。第五个是 2026-11-19 联调补丁新增的，
**必须执行**，否则风控解除审批接口会因为缺表报 500。
带 `CREATE TABLE IF NOT EXISTS` 的脚本可以重复执行；`s3-incremental.sql` 里的
`ALTER TABLE audit_log DROP CHECK` 重复执行会报"约束不存在"，已执行过的库不用重跑。

用 mysql 客户端执行，例如：

```
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p123456 -D payment_db < deploy/sql/s2-requirement-gaps-incremental.sql
```

另外：JAR 必须与源码同步。如果改了后端代码但没重新构建，
运行的还是旧 JAR，新接口会出现 404。构建前要先停掉服务，否则 JAR 被占用无法 clean。

### 已有数据库需要补 approved_by 列

`RiskListService.list()` 查询 `risk_list_entry` 时会读 `approved_by` 列。
早期增量脚本建的表没有这一列，导致"风险名单"和"变更审批"报 500。
新脚本和 `deploy/sql/schema.sql` 已补上该列。已经建好的库要手动执行一次：

```sql
ALTER TABLE payment_db.risk_list_entry
  ADD COLUMN approved_by VARCHAR(64) DEFAULT NULL COMMENT '审批人身份';
```

重复执行会报"列已存在"，属于正常提示，可忽略。

## 端口与令牌

| 服务 | 端口 |
|---|---|
| user-service | 8081 |
| account-service | 8082 |
| transaction-service | 8083 |
| risk-service | 8084 |
| gateway | 8090（8080 常被占用） |
| 前端 Vite | 5173 |

前端 Vite 的 `/api` 代理目标是网关 8090（见 `frontend/vite.config.js`）。
如果改了网关端口，必须同步改这里的代理目标，否则页面所有请求都会返回 HTTP 500。

脚本顶部集中定义了数据库密码和三个内部令牌。当前值是本机演示配置（root / 123456 等）。
换环境时改 `start-all.ps1` 开头的 `$DbUrl`、`$DbUser`、`$DbPassword`、`$BankToken`、
`$AccountToken`、`$RiskToken` 六个变量即可。

## 一个必须显式设置的坑

本机 bash 沙箱预设了 `SERVER_PORT` 环境变量，会覆盖 `application.yml` 里的默认端口。
曾导致 5 个服务全部读到同一个端口而互相冲突。
所以脚本对每个服务都显式设置 `SERVER_PORT=80xx`，不要删掉这些行。

## 后台账户查询接口（2026-11-19 新增）

`GET /api/v1/accounts/scoped` 是独立接口。它只返回当前员工会话被授权的账户，
并且必须带 `reason`（查询原因，至多 200 字）。服务端会把查询写进 `audit_log`，
动作是 `BACKOFFICE_ACCOUNTS_QUERY`。普通客户调用返回 403。

`GET /api/v1/accounts`（我的账户）只返回本人名下账户，不再把授权范围账户并进来。
员工账号在前端也不显示个人银行业务菜单。

- 运营在「运营管理 → 按授权范围查账户」填原因后查询，可以对账户冻结或解冻。
- 风控在「风险控制 → 冻结解除审批」登记 RISK 冻结的解除结论。
- 运营解冻时必须提交全部当前有效限制编号；风控来源的限制要先有解除结论，否则后端拒绝。
- 后台身份查交易详情、回单、资金流水都要带 `reason`，前端已统一带上。

改了后端源码后必须重新 `mvnw.cmd clean install` 再重启服务，否则新接口仍是 404。

## 关于日志

每个服务的日志写在 `logs/<服务名>.log`，前端日志在 `logs/frontend.log`。
如果某个服务没起来，先看对应日志的最后 20 行。

## 关于自动化工具环境的限制

在非交互的自动化会话里（例如 AI 工具调用 PowerShell），`Start-Process` 启动的子进程
会随会话结束被系统回收，所以脚本报告的 `UP` 在会话结束后会失效。
这不是脚本的问题：**在您自己双击 .bat 的交互桌面会话里，服务会正常保留**。
脚本日志里出现 `Started XxxApplication` 即表示启动逻辑本身正确。
