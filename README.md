## 1. 项目简介

本项目按实验指导书**选题一**要求，构建一个模拟现代数字银行核心业务的分布式系统，覆盖
**存款、取款、跨行转账、风控**等关键金融业务，采用高内聚、低耦合的微服务架构，
应对复杂业务规则与高一致性要求。

**核心目标**

| 目标 | 对应实验 | 验收方式 |
|---|---|---|
| 完成需求调研、用户故事地图、UML 分析模型 | 实验一 | `docs/01-需求规格说明书/` |
| 完成架构选型与 UML 设计模型 | 实验二 | `docs/02-设计规格说明书/` |
| 至少打通一条端到端业务流程（存款） | 实验三 | `docs/03-原型实现/` + 代码 |
| 完成测试方案、用例与部署方案 | 实验四 | `docs/04-测试报告/` |

**业务范围（In Scope）**

- 用户开户、实名信息维护、登录认证
- 账户管理：活期账户开立、余额查询、账户冻结/解冻
- 存款、取款、本行转账、跨行转账（跨行以模拟清算行实现）
- 交易流水记录、对账查询
- 风控：单笔限额、日累计限额、异常交易拦截

**非目标（Out of Scope）**

- 真实对接人行支付系统 / 银联（一律模拟）
- 真实资金清算、利息计息、贷款业务
- 生产级安全合规认证（仅做基础权限与数据校验）

## 3. 技术栈

> 状态列：`已定` = 已达成一致；`待定` = 实验二架构决策时确定（见 ADR）。
> **实验二要求至少对比两种架构方案**，技术选型理由请记录到 `docs/02-设计规格说明书/架构决策记录.md`。

| 层次 | 选型 | 状态 | 说明 |
|---|---|---|---|
| 前端 | Vue 3 + Vite + Element Plus | 待定 | 备选 React + Ant Design |
| 后端 | Spring Boot 3 (Java 17) | 待定 | 备选 Express.js / Django |
| 服务注册与配置 | Nacos / Eureka | 待定 | 视后端语言而定 |
| 网关 | Spring Cloud Gateway | 待定 | 统一鉴权、路由 |
| 数据库 | MySQL 8 | 待定 | 账户/交易强一致，需事务 |
| 缓存 | Redis | 待定 | 会话、幂等键、限流 |
| 消息队列 | RabbitMQ / Kafka | 待定 | 风控异步事件（可选） |
| 容器化 | Docker + Docker Compose | 待定 | 实验四部署方案 |
| 建模工具 | PlantUML（源码入库） | 已定 | 图源文件必须提交，禁止只交截图 |
| 版本控制 | Git + GitHub | 已定 | 主干 main + 特性分支 |

`out/` 目录。这样图能 diff、能 review、能追溯谁改了什么。

## 4. 系统架构（规划草案）

> ⚠️ 以下为**初始假设**，服务边界需在实验二通过领域建模与限界上下文分析后确认，
> 不得直接当作最终设计写入实验报告。

| 服务 | 职责 | 核心实体 |
|---|---|---|
| `gateway` | 统一入口、鉴权、限流、路由 | — |
| `user-service` | 客户信息、实名认证、登录 | Customer, Identity |
| `account-service` | 账户开立、余额、冻结 | Account, AccountStatus |
| `transaction-service` | 存款/取款/转账、流水、幂等 | Transaction, TransferOrder |
| `risk-service` | 限额校验、异常交易拦截、风控规则 | RiskRule, RiskEvent |

**关键设计约束**

1. **余额一致性**：转账涉及两个账户，必须保证要么全成功要么全回滚（本地事务 or Saga）。
2. **幂等性**：同一笔交易重复提交不得重复扣款，需交易流水号唯一约束 + 幂等表。
3. **审计**：所有资金变动必须留流水，流水不可修改、只能追加。

## 6. 迭代计划

指导书要求：敏捷开发，1-2 周一个迭代，每个迭代结束交付**可工作的软件增量**。

| Sprint | 周期 | 核心目标 | 交付物 |
|---|---|---|---|
| Sprint 0 | 第 1 周 | 立项、仓库与协作规范、需求调研 | 本 README、BACKLOG、用例图初稿 |
| Sprint 1 | 第 2-3 周 | 需求分析与迭代规划（实验一） | 需求规格说明书、用户故事地图、域模型 |
| Sprint 2 | 第 4-5 周 | 系统设计与技术选型（实验二） | 架构决策记录、包图、部署图、序列图、库表设计 |
| Sprint 3 | 第 6-8 周 | 原型构建与实现（实验三） | 可运行原型、存款端到端流程、核心代码 |
| Sprint 4 | 第 9-10 周 | 测试与部署（实验四） | 测试用例与记录、部署方案、实验报告定稿 |

进度看板见 **Projects** 页面（Backlog / In Progress / Review / Done 四列）。

## 8. 协作规范（摘要）

- **分支**：`main` 受保护，禁止直接 push；功能分支 `feat/<模块>-<简述>`、修复 `fix/<简述>`。
- **提交**：遵循 Conventional Commits，如 `feat(account): 实现账户开立接口`。
- **合并**：必须走 Pull Request，至少 1 人 Review 通过后 squash 合并。
- **任务**：所有工作先建 Issue，PR 描述里写 `Closes #12`。

完整规范见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 9. 快速开始

> 待 Sprint 3 首个可运行版本完成后补充。目标形态：

```bash
# 1. 克隆
git clone <repo-url> && cd digital-bank-core

# 2. 启动依赖（MySQL / Redis）
docker compose -f deploy/docker-compose.dev.yml up -d

# 3. 启动后端
cd backend && ./mvnw spring-boot:run

# 4. 启动前端
cd frontend && npm install && npm run dev
```
