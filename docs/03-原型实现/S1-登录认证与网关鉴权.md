# S1 · 登录认证与网关鉴权

## 1. 已实现的范围

- `POST /api/v1/auth/login`：按 identityId 和 password 校验凭据，返回会话。
- `GET /api/v1/auth/me`：返回当前登录客户的业务标识。
- `POST /api/v1/auth/logout`：撤销当前令牌；再次使用返回 401。
- `GET /internal/v1/auth/session`：供网关及业务服务核验会话，同时要求内部服务密钥。
- 网关使用非阻塞 WebClient 核验会话；Servlet 业务服务使用公共过滤器独立复核。
- 公共 `AccessService` 提供当前身份和资源归属校验，供 S2/S3 接入。

注册、实名、客户资料、角色管理及账户/交易业务不在本次实现范围。

## 2. 代码位置

| 模块 | 位置 | 职责 |
|---|---|---|
| common | `auth/` | 令牌解析、会话身份、内部服务密钥、远程会话核验、对象归属检查 |
| common | `web/AuthenticationFilter` | 对非公开请求核验令牌，把已核验身份写入 request attribute |
| user-service | `controller/` | HTTP 入参和响应，不包含密码或会话存储逻辑 |
| user-service | `service/SessionService` | 密码校验、会话核验、停用/改密失效及退出 |
| user-service | `repository/` | 演示凭据、JDBC 凭据查询、内存会话存储 |
| gateway | `service/GatewaySessionVerifier` | 非阻塞访问用户服务，不在事件循环中使用 block() |
| gateway | `filter/AuthenticationWebFilter` | 精确白名单、鉴权失败响应、删除客户端身份头 |

以上 Java 路径均相对于对应模块的 `src/main/java/com/digitalbank/` 包。

## 3. 认证约定

登录请求：

```json
{"identityId": "demo-user", "password": "<本地自行设置的密码>"}
```

成功响应的 data：

```json
{
  "token": "<随机会话令牌>",
  "tokenType": "Bearer",
  "expiresAt": "2026-11-10T08:30:00Z",
  "customer": {
    "customerId": "DEMO-CUSTOMER-001",
    "identityId": "demo-user"
  }
}
```

后续请求放在请求头：`Authorization: Bearer <token>`。
`expiresAt` 为 UTC 时间，前端按本地时区展示。认证登录和退出不要求金融业务的 requestId。

密码使用 Spring Security 的 BCrypt（强度 12）校验，凭据仓库仅保存哈希。
BCrypt 限制为 72 字节，接口同时检查字符数和 UTF-8 字节数。
错误密码、未知用户和不可用凭据统一返回 401，不公开具体用户状态。
密码和令牌相关 DTO 的 toString 做脱敏，不在日志中记录密码或完整令牌。
密码存储依据：[Spring Security Password Storage](https://docs.spring.io/spring-security/reference/6.5/features/authentication/password-storage.html)。

会话使用 SecureRandom 生成 32 字节随机令牌；服务端只保存令牌 SHA-256 指纹。
默认固定有效期为 30 分钟，不因访问而续期；退出后撤销对应会话。
客户冻结/注销、凭据锁定/注销、密码哈希变化及用户删除都会使原会话失效。
会话最多 10,000 条，定期清理过期项；容量满时返回 503。

当前会话在用户服务内存中：重启用户服务后需要重新登录，暂不支持多个用户服务实例共享会话。
本次未实现刷新令牌、登录频率限制及角色管理。

## 4. 本地演示启动

无需数据库即可演示认证，但必须显式设置演示用户和服务密钥，没有默认登录密码。

先在 PowerShell 7 生成一份内部服务密钥：

```powershell
$env:BANK_INTERNAL_TOKEN = [Convert]::ToHexString(
    [System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32)
)
```

把**同一个值**配置到 IDEA 中五个服务的 Environment variables，变量名均为 BANK_INTERNAL_TOKEN。
不要给每个服务分别生成不同值。密钥不配置或短于 32 字符时，受保护的跨服务访问会返回 503。
不要把真实密钥保存进 Git。

在用户服务的运行配置中，额外设置：

```text
BANK_CREDENTIAL_STORE=demo
BANK_DEMO_ENABLED=true
BANK_DEMO_IDENTITY=demo-user
BANK_DEMO_PASSWORD=<自行设置的12到72字节密码>
```

演示用户的 customerId 固定为 `DEMO-CUSTOMER-001`，不表示真实数据库中已存在该客户。
默认 BANK_DEMO_ENABLED=false，此时没有演示用户，不能使用示例身份直接登录。
`backend/.env.example` 仅用于说明变量；Spring Boot 不会自动加载 .env 文件。

构建后启动五个 Application。端口和常规构建命令见 `backend/README.md`。
如果只调试登录、当前用户和退出，启动用户服务与网关即可。

PowerShell 请求示例：

```powershell
$loginBody = @{
    identityId = "demo-user"
    password = $env:BANK_DEMO_PASSWORD
} | ConvertTo-Json

$login = Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8080/api/v1/auth/login" `
    -ContentType "application/json" `
    -Body $loginBody

$headers = @{ Authorization = "Bearer " + $login.data.token }

Invoke-RestMethod `
    -Uri "http://localhost:8080/api/v1/auth/me" `
    -Headers $headers

Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:8080/api/v1/auth/logout" `
    -Headers $headers
```

如果密码只配置在 IDEA 中，需要在调用请求的终端中单独设置 BANK_DEMO_PASSWORD。
退出后重复调用 me，应返回 HTTP 401。

## 5. S4：接入 MySQL

在用户服务设置以下变量，其他服务只需要用户服务地址与相同内部密钥：

```text
BANK_CREDENTIAL_STORE=mysql
BANK_DB_URL=jdbc:mysql://localhost:3306/payment_db?serverTimezone=Asia/Shanghai&characterEncoding=UTF-8
BANK_DB_USERNAME=<用户服务数据库账号>
BANK_DB_PASSWORD=<数据库密码>
```

查询直接对接实验二 `customer` 与 `credential` 的字段，不自行建立第二套用户表。
按 customer.identity_id 查客户，再选取该客户最早的 USERNAME 类型凭据。
登录要求 customer.status 和 credential.status 均为 NORMAL。
credential.password_hash 必须存 BCrypt 格式哈希；明文和其他格式不能直接登录。

本次仓库只查询凭据，不写入或重建业务数据库。S4 负责初始化真实客户与凭据、数据库授权和后续连接池配置。
已使用 H2 的 MySQL 模式验证查询、字段映射及参数绑定；尚未连接真实 MySQL 验证。

## 6. S2/S3：对象权限与服务调用

直接访问业务服务端口同样要求 Bearer 令牌，不能通过伪造 X-Customer-Id 或 X-Identity-Id 绕过验证。
网关会删除客户端携带的身份及内部服务密钥请求头，下游仍根据令牌核验真实身份。

在业务 Controller/Service 中注入 `AccessService`，查询出资源所有者后执行：

```java
SessionIdentity current = accessService.currentIdentity(request);
accessService.requireOwner(request, account.getCustomerId());
```

读取本人身份使用 current.customerId()，不要直接读取客户端请求头中的 customerId。
归属不匹配返回 403；对象查询是否需要统一映射为 404，由对应业务接口契约决定。

后续业务服务间 HTTP 调用需继续传递 Authorization 和 X-Trace-Id。
用户会话核验内部接口额外要求 X-Service-Token；其他内部记账接口仍由对应模块实现服务身份校验。
网关对 `/internal/**` 始终返回 404。

## 7. 错误与验收

| HTTP | code | 含义 |
|---|---|---|
| 400 | INVALID_ARGUMENT | 请求字段不合法，包括超过 BCrypt 字节限制 |
| 401 | UNAUTHENTICATED | 缺少、错误、过期、已撤销令牌或登录失败 |
| 403 | FORBIDDEN | 对象归属校验不通过 |
| 503 | SERVICE_UNAVAILABLE | 核验依赖或凭据存储不可用、内部密钥未配置或会话容量满 |

核验依赖发生错误时拒绝放行，不能把 503 当作登录成功，也不应清空凭据后静默继续操作。
登录、会话查询、退出及认证拒绝响应使用 Cache-Control: no-store。

验证命令：

```powershell
# backend 目录
.\mvnw.cmd -s .mvn/central-settings.xml clean install
python scripts/smoke.py
```

22 项测试覆盖基础设施、登录接口、会话生命周期、对象归属和 JDBC 查询。
五进程冒烟脚本使用随机临时密钥和密码，验证网关转发、直接端口防绕过、伪造身份头、退出失效，
并主动停止用户服务验证依赖故障返回 503。脚本结束后停止测试进程。
