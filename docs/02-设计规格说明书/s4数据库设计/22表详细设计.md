## 二、逐表设计

### 2.1 用户与认证（user-service）

#### `customer` 客户表（11 列 / 4 索引 / 0 外键 / 2 CHECK）

- 业务主键：`customer_id`（`uk_customer_customer_id`）；对外身份：`identity_id`（`uk_customer_identity_id`）
- 其他唯一键：`uk_customer_phone`
- 普通索引：`idx_customer_status`
- CHECK：`status ∈ {NORMAL, FROZEN, CANCELLED}`；`real_name_status ∈ {UNVERIFIED, VERIFIED, REJECTED}`
- 读写：user-service 读写；account-service 只读
- 设计要点：`customer_id` 与 `identity_id` 是两个不同口径，前者做表间外键，后者做幂等与对外交互；`version` 乐观锁

#### `credential` 登录凭证表（9 列 / 2 索引 / 1 外键 / 2 CHECK）

- 主键自增 `id`；唯一键 `uk_credential_username`
- 外键 `fk_credential_customer → customer.customer_id`
- 索引 `idx_credential_customer`
- CHECK：`credential_type`、`status` 取值域
- 口令存储：BCrypt `$2a$12$`（成本因子 12），禁止明文/可逆加密
- 读写：user-service 独占

#### `user_command` 用户命令幂等表（7 列 / 1 索引 / 0 外键 / 0 CHECK）

- 联合主键 `(identity_id, command_type, request_id)` 即幂等键
- `request_hash` 保存请求摘要：同键不同内容判为冲突，不执行业务
- 读写：user-service 独占

#### `staff_authorization` 员工角色表（4 列 / 0 索引 / 0 外键 / 1 CHECK）

- 主键 `identity_id`（一人一角色，避免多角色歧义）
- 字段：`role_id`、`version`（乐观锁）
- CHECK：`role_id ∈ {OPERATIONS, RISK, ADMIN}`
- 读写：user-service 读写（登录时装配会话角色）

#### `staff_account_scope` 员工账户范围表（2 列 / 0 索引 / 1 外键 / 0 CHECK）

- 联合主键 `(identity_id, account_id)`
- 外键 `→ account.account_id`
- 语义：后管身份可操作的账户白名单；为空即无任何数据权限（登录返回空范围，接口 403）

### 2.2 账户与记账（account-service）

#### `account` 账户表（12 列 / 3 索引 / 1 外键 / 6 CHECK）

- 业务主键 `account_id`（`uk_account_account_id`）；外键 `→ customer.customer_id`
- 索引：`idx_account_customer`、`idx_account_status`
- CHECK：账户状态、账户类型、币种、余额非负、可用额不超余额等
- 关键字段：`book_balance`（账面余额）、`reserved_amount`（预留/占用）、可用额 = 差额
- 并发控制：`version` 乐观锁 + 预留表配合，避免超扣

#### `account_status_log` 账户状态变更记录（9 列 / 1 索引 / 1 外键 / 2 CHECK）

- 索引 `idx_account_status_log_account_created`（账户 + 时间）
- 外键 `→ account.account_id`
- 用途：冻结/解冻/注销的不可变留痕；`risk_freeze_release` 以本表 `id` 为父键

#### `account_command` 账户命令幂等表（7 列 / 0 索引 / 0 外键 / 0 CHECK）

- 联合主键 `(identity_id, command_type, request_id)` + `request_hash`
- 读写：account-service 独占

#### `account_reservation` 账户预留表（6 列 / 1 索引 / 2 外键 / 2 CHECK）

- 索引 `idx_reservation_account_day`
- 外键：`→ account`、`→ transaction`（预留与交易一一对应）
- 用途：出账前占用额度，成功转扣减、失败释放，保证"不超可用额"

#### `risk_freeze_release` 冻结解除审批表（4 列 / 0 索引 / 1 外键 / 0 CHECK）

- 主键 `restriction_id`，外键 `→ account_status_log(id)`
- 字段：`approved_by`、`basis`、`approved_at`
- 语义：一条冻结限制只有在存在审批记录时才允许解除；`basis` 为必填依据
- 读写：risk-service 写入审批；account-service 用 `LEFT JOIN` 判断"是否已审批"
- 说明：本表为 main@27a7974 新增，是 21 表 → 22 表的唯一增量

### 2.3 交易与渠道（transaction-service）

#### `transaction` 交易表（19 列 / 6 索引 / 1 外键 / 4 CHECK）

- 业务主键 `trade_no`（`uk_transaction_trade_no`）；幂等唯一键 `uk_transaction_request (identity_id, request_id)`
- 外键 `→ account.account_id`
- 索引：`idx_transaction_status`、`idx_transaction_account_created`、`idx_transaction_accepted_account`、`idx_transaction_request_lookup`
- CHECK：7 态状态机取值、金额为正、币种、业务类型
- 关键字段：`status`（ACCEPTED/PROCESSING/UNKNOWN/SUCCESS/RECOVERING/FAILED/REJECTED）、`channel_evidence_id`、`last_channel_result`
- 读写：transaction-service 写；account-service 只读更新状态；risk-service 只读

#### `transaction_flow` 资金流水表（11 列 / 4 索引 / 2 外键 / 4 CHECK）

- 唯一键 `uk_transaction_flow_entry_id`、`uk_transaction_flow_role (trade_no, role)`（同笔交易每角色一条，防重复记账）
- 外键：`→ account`、`→ transaction`
- 用途：借贷双向流水，余额变动的唯一事实来源

#### `transfer_order` 转账单表（14 列 / 5 索引 / 3 外键 / 5 CHECK）

- 唯一键 `uk_transfer_order_transfer_id`、`uk_transfer_order_trade_no`
- 索引：`idx_transfer_order_payer`、`idx_transfer_order_payee`、`idx_transfer_order_clearing`
- 外键：`→ account`（付款方、收款方）、`→ transaction`
- 用途：跨行/内部转账单据与清算状态

#### `mock_channel_deposit` 模拟渠道入金记录（14 列 / 3 索引 / 2 外键 / 3 CHECK）

- 唯一键 `uk_channel_request`（渠道幂等）；索引 `idx_channel_next_check`（扫描待核对）
- 外键：`→ account`、`→ transaction`
- 用途：模拟外部渠道的成功/失败/未知回执，支撑"未知态 → 人工核对/自动重试"

#### `trade_manual_action` 人工操作幂等留痕（8 列 / 2 索引 / 0 外键 / 1 CHECK）

- 唯一键 `uk_manual_action (identity_id, action, request_id)`
- 索引 `idx_manual_action_trade`
- 字段：`action ∈ {RECONCILE, RECOVER}`、`conclusion`、`channel_result`
- 用途：人工核对/恢复重试的幂等与审计双职责；同请求重复提交返回首次结果

### 2.4 风控（risk-service）

#### `risk_rule` 风控规则表（11 列 / 2 索引 / 0 外键 / 5 CHECK）

- 业务主键 `rule_id`（`uk_risk_rule_rule_id`）；索引 `idx_risk_rule_type_enabled`
- CHECK：限额非负、`rule_type` 取值域
- 初始数据：`RK-01 ACCOUNT_STATUS`、`RK-02 LIMIT_POLICY`（存款 50000 / 出账 10000 / 日累计 50000）
- 变更必须走审批单，`rule_version` 随审批递增

#### `risk_event` 风险事件表（11 列 / 3 索引 / 2 外键 / 3 CHECK）

- 业务主键 `event_id`（`uk_risk_event_event_id`）
- 索引：`idx_risk_event_trade_no`、`idx_risk_event_rule_created`
- 外键：`→ risk_rule`、`→ transaction`
- 用途：规则命中留痕（含 `result=REJECT/PASS`、`reason_code`）

#### `risk_alert_disposal` 告警处置留痕（10 列 / 2 索引 / 0 外键 / 1 CHECK）

- 唯一键 `uk_alert_disposal`、索引 `idx_alert_disposal_event`
- CHECK：`decision ∈ {CONFIRMED, FALSE_POSITIVE, ESCALATED}`
- 幂等：同一 `request_id` 重复提交返回首次结果

#### `risk_change_request` 风控变更审批单（14 列 / 3 索引 / 0 外键 / 2 CHECK）

- 唯一键 `uk_change_request`、`uk_change_id`；索引 `idx_change_status`
- 字段：`change_json`（变更快照）、`status ∈ {PENDING, APPLIED, REJECTED}`、`submitted_by`
- 规则：提交人与审批人不得相同（服务层校验）

#### `risk_change_approval` 风控审批留痕表（8 列 / 2 索引 / 0 外键 / 1 CHECK）

- 唯一键 `uk_change_approval (change_id)`：一单只能审批一次
- 索引 `idx_approval_change`
- 用途：审批结论不可变留痕；重复审批由唯一键兜底

#### `risk_list_entry` 风险名单条目表（13 列 / 3 索引 / 0 外键 / 3 CHECK）

- 唯一键 `uk_list_entry (entry_id)`、`uk_list_subject (list_type, subject_type, subject_id)`
- 索引 `idx_list_subject`
- CHECK：`list_type ∈ {BLACKLIST, WHITELIST}`、`subject_type ∈ {ACCOUNT, CUSTOMER}`、`enabled ∈ {0,1}`
- 关键设计：同一主体只允许一条记录 → 更新必须按业务唯一键定位（`entry_id` 每次提交会变）
- `approved_by`：main 已并入，审批人留痕

### 2.5 共享

#### `audit_log` 审计日志表（12 列 / 3 索引 / 0 外键 / 1 CHECK）

- 索引：`idx_audit_log_operator_created`、`idx_audit_log_trade_no`、`idx_audit_log_target`
- 用途：所有后管操作（查询带 reason、处置、审批、人工核对）写一条
- 授权收紧：4 个业务账号仅 `INSERT`（user-service 另加 `SELECT`），不可改不可删

## 三、全局设计约定

1. **主键**：每表都有主键；业务表另设业务键（`customer_id`/`account_id`/`trade_no`/`event_id`），窗口函数与幂等基于业务键。
2. **幂等**：写接口统一 `(identity_id, request_id)` + `request_hash`，同键同内容返回首次结果，同键异内容抛 `REQUEST_CONFLICT`。
3. **并发**：账户用 `version` 乐观锁 + `account_reservation` 预留，双重防超扣。
4. **金额**：全库 `DECIMAL(18,2)`，禁止浮点。
5. **时间**：`DATETIME` + 默认 `CURRENT_TIMESTAMP`，统一 `Asia/Shanghai`。
6. **外键**：17 条全部带 `fk_` 前缀，删除顺序在建表脚本开头统一 `DROP`。
7. **CHECK**：48 条，MySQL 8.0.16+ 强制；8.0.13 会静默丢弃（本项目已升级 8.0.46 规避）。
8. **字符集**：库/表/连接三处统一 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`。

## 五、索引设计说明（高频路径）

## 六、与 DDL 的一致性

