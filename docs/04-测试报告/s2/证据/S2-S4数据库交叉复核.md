# S2 与 S4 的数据库证据复核

来源为 S4 实验四压缩包中的《S4-实验四对外交接.md》《S4-部署与数据库验证记录.md》、`verify-output-20261117-152347.txt` 和《验证输出-实验四.txt》。单独发来的交接文档与包内文件的 SHA-256 一致。以下是 S4 在 2026-11-17 的实测输出摘录。

| 对应记录 | S4 实际结果 | S2 使用方式 |
|---|---|---|
| DEP-S4-001/002 | MySQL 8.0.13，13 张表、15 个外键 | 核对账务表和逐笔预留表齐备 |
| DEP-S4-005/006 | 重复原单触发 `1062 / uk_transaction_request`，重复流水触发 `1062 / uk_transaction_flow_role` | 作为幂等和流水唯一性的数据库约束证据 |
| DEP-S4-007/008 | `ACC_S2_001` 的 B/R/A 为 50000.00/0.00/50000.00，`ACC_S2_002` 为 30000.00/0.00/30000.00。SQL 演练单 `VERIFY-DEPO-0001` 的 B 从 50000.00 到 50100.00，只有一条 `DEPOSIT_IN/CREDIT` 100.00 | 关联余额不变式和资金流水。该演练由 `verify.sql` 插入原单和流水并直接更新余额 |
| DEP-S4-009/010 | `account_service` 具备所需表读写和 `LOCK TABLES`。`RK-02` 启用，存款单笔 50000.00，出账单笔 10000.00，出账日累计 50000.00 | 作为部署口径和联调边界值依据 |
| DEP-S4-003 | `check_count=0`，S4 记录 DEF-S4-001 | 约束验收需要在启用 CHECK 的版本复核。 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.0/en/create-table-check-constraints.html) |
| DEP-S4-012/013 | 五服务健康检查和经网关存款冒烟均标为未执行 | S4 所列 `18080` 为本机启动约定，验收使用实际运行确认的网关地址 |

S4 日志确认账号 `UID-000001` 与 `ACC_S2_001` 可用于存款核账，`UID-000002` 与 `ACC_S2_002` 可用于对象访问边界。S4 确认了演示凭据存有 BCrypt 哈希。真实登录、交易状态和资金变动应以接口和 SQL 的执行记录为准。

联调时使用 `s2_readonly` 读取 `payment_db` 的账户、预留、原单和流水。渠道记录由 S4 或 S3 按 `tradeNo` 补报。取证记下 `requestId`、`tradeNo`、`traceId`，保存首次请求前、成功后和重放后的 SQL 结果。S4 的 `verify.sql` 会直接写入测试原单和账户余额，`init-data.sql` 会清理演示库中的数据，两个脚本适用于可重置的测试库。
