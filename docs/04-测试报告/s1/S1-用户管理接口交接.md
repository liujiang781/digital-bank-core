# S1 新增接口与联调说明

日期：2026-11-18。基于 `80b44f6`，分支 `feat/s1-user-management`。

## 1. 本次完成的接口

| 方法 | 路径 | 功能与权限 |
|---|---|---|
| POST | `/api/v1/auth/register` | 匿名注册并完成教学模拟实名，创建客户及 BCrypt 凭据 |
| GET | `/api/v1/customers/me` | 查询本人资料，身份、手机号和邮箱脱敏 |
| PUT | `/api/v1/customers/me` | 仅修改本人手机号、邮箱；不能改身份、实名姓名、状态或角色 |
| GET | `/api/v1/customers?reason=核查&page=1&pageSize=20` | 运营按账户范围查询客户及账户状态；支持 `status` 筛选 |
| GET | `/api/v1/roles?identityId=目标身份` | 管理员查询某身份的角色、账户范围和授权版本 |
| PUT | `/api/v1/roles/{roleId}` | 管理员替换某身份的业务角色与账户范围，或撤销全部业务授权 |

所有写接口要求 UUID 格式的 `requestId`。相同身份、操作、请求号及内容重复提交返回原结果；内容改变返回 409。写入、幂等记录及成功审计在同一事务提交。

## 2. 启动前准备（S4 配合）

1. 已有库执行 `deploy/sql/s1-incremental.sql`，只新增三张表，不删除旧数据。新建库使用更新后的 `schema.sql`，已经包含这三张表。
2. 用户服务设置 `BANK_CREDENTIAL_STORE=mysql`，沿用 `BANK_DB_URL`、`BANK_DB_USERNAME`、`BANK_DB_PASSWORD`。demo 模式只供预置账号登录，不支持本次需要持久化的注册、资料和在线授权接口，调用时返回 503。
3. 用户数据库账号需要：`customer` 的 SELECT/INSERT/UPDATE；`credential` 的 SELECT/INSERT；`account` 的 SELECT；`audit_log` 的 INSERT；`user_command` 的 SELECT/INSERT/UPDATE；`staff_authorization` 的 SELECT/INSERT/UPDATE；`staff_account_scope` 的 SELECT/INSERT/DELETE。无须授予余额写权限。
4. 管理员凭据由 S4 预置（客户/凭据正常状态，密码为 BCrypt）。用户服务额外加载 `deploy/auth-admin.example.yml`，默认配置的管理员身份为 `OPS-ADMIN`，可以改为实际已存在的身份；配置不提供口令，也不会自动创建管理员。
5. 网关和业务服务与用户服务共用正确的 `BANK_INTERNAL_TOKEN`。本次会话多了 `authorizationVersion`，各服务应使用本次构建的 common 一起重启，旧内存会话需重新登录。

这不是对接真实公安或银行实名系统：姓名去除首尾空格后至少两个字符，身份为 3—64 位字母、数字、下划线或短横线；通过格式校验后标记 VERIFIED。注册不能抢占服务端预置的员工/管理员身份。

## 3. 请求示例（S5 对接）

注册：

```json
{"realName":"测试客户","identityId":"USER-NEW-001","password":"自行设置的密码","requestId":"721e6ec7-e171-420b-a457-26a59dca11b1"}
```

返回 `customerId` 和 `realNameStatus`。注册不自动登录；随后调用现有登录接口，取得 Bearer 令牌。密码 6—72 个字符且不超过 72 个 UTF-8 字节，服务端不保存明文。

修改资料：

```json
{"phone":"13812345678","email":"member@example.com","requestId":"d7409bd6-b1e4-40b0-8d51-615367d6ffb9"}
```

PUT 使用完整可修改资料，`null` 或省略字段表示清空对应联系方式；不支持通过该接口改密码、实名信息或角色。响应中的身份和联系方式是脱敏展示值，不应直接回填为下次修改输入。

管理员授予运营角色：`PUT /api/v1/roles/OPERATIONS`。

```json
{"identityId":"目标已注册身份","enabled":true,"accountScope":["ACC_S2_001"],"reason":"分配运营岗位","requestId":"428021d5-a8a0-4275-9fbc-649bc30710ca"}
```

`roleId` 只允许 OPERATIONS 或 RISK。一次替换该身份全部业务角色和范围，当前在线模型每个身份只有一个业务岗位，避免多个角色的账户范围串用。`enabled=false` 且 `accountScope=[]` 表示撤销全部业务授权；空授权记录覆盖旧静态配置，防止撤权后又自动获得旧权限。

ADMIN 仅由服务端配置，不能通过接口授予、修改或撤销。管理员不能查询客户/账户/交易业务数据；角色管理只返回授权信息。普通用户和运营都不能调用授权管理接口。授权账户必须真实存在且未注销，不能使用通配符。

每次成功授权变更都会增加版本，旧令牌下次访问返回 401，目标身份重新登录后获得新权限。重复请求不增加版本；授权恢复成过去相同的角色和范围也不会让旧令牌重新生效。

## 4. 测试与复现

新增集成测试覆盖注册、并发重放、不同内容冲突、注册/资料/授权事务回滚、字段保护、范围过滤、授权变更与撤销、旧令牌失效和管理员隔离。

实际结果：后端合计 **228 项测试通过**（其中新用户管理集成测试 20 项），三服务间 **29 个真实 HTTP 场景通过**。证据见 [2026-11-18 执行记录](证据/2026-11-18/README.md)。前端 API 封装已增加 `getProfile`、`listCustomers`、`getAuthorization`、`updateAuthorization`，供 S5 接入页面。

打包全部后端后，在仓库根目录运行下面的脚本，可验证真实网关→用户服务→账户服务的注册、登录、开户与动态授权链路：

```powershell
python backend/scripts/user_management_smoke.py --java E:/Java/jdk-21/bin/java.exe --h2-jar ../tools/maven-repository/com/h2database/h2/2.3.232/h2-2.3.232.jar --output docs/04-测试报告/s1/证据/2026-11-18/user-management-http.json
```

脚本使用临时 H2 数据库与随机口令，不连接现有 MySQL。测试结束自动停止自己创建的进程，证据中的口令和令牌脱敏。真实 MySQL 迁移和部署验收由 S4 按上述准备步骤另行执行。
