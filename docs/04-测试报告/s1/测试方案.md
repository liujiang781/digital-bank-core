# 实验四测试方案

本轮以 S1 的认证与网关为主，复用并执行账户、交易、风控已有自动化测试。测试目标是确认合法用户能登录和访问服务，非法凭据、伪造身份与内部接口访问被阻止，并明确当前版本尚未完成的真实资金联调范围。

## 测试基线与环境

代码基线为 4adeb17 及本次工作区修改，日期为 2026-11-17。关键源文件 SHA-256 见证据目录 source-sha256.json。环境为 Windows、JDK 21.0.7、Maven 3.9.11、Spring Boot 3.5.7。组件测试使用 JUnit 5、AssertJ、Spring 测试上下文和 H2；网关过滤器测试使用模拟交换对象及会话验证替身。真实 HTTP 使用独立 JVM 的 user-service 与 gateway，随机本机端口及 demo 凭据，不连接 MySQL。

## 范围与方法

S1：登录、用户令牌语法、会话过期与撤销、伪造身份头、内部服务令牌、网关路由保护、演示凭据兼容性。对 AuthTokens.requireBearer(List<String>) 按短路条件拆分控制流，计算 V(G)，设计六条独立路径与七个补充边界用例。功能测试先划分有效和无效等价类，再经真实 HTTP 执行 17 个场景。

全组回归：运行账户与记账、内部和跨行转账、幂等、金额与请求标识、风控已有测试。H2 和替身测试结果分别记录，不替代真实 MySQL 和五服务资金链路的验收。

## 执行过程

1. 固定代码版本、JDK、Maven 与输入数据，记录源文件校验值。
2. 执行组件测试，按 Surefire XML 汇总，不从旧报告复制结果。
3. 用随机端口启动两个独立 JVM，执行认证 HTTP 用例，保存脱敏请求响应，并在 finally 中关闭测试进程。
4. 修复测试或检查发现的问题，回归受影响模块；前端配置修改后重新构建。
5. 记录缺陷、未执行项、证据路径和结果统计，由本人复核后与组员材料汇总。

## 进入与退出准则

进入条件：JDK 21 与 Maven 可用、依赖可解析、测试夹具和所选代码匹配。认证 HTTP 测试只需可用本机回环网络；真实资金联调还需 MySQL、正确服务令牌、真实凭据和五个服务。

S1 退出条件：六条令牌独立路径及认证正反例均有执行证据；已有认证回归通过；缺陷修复关联到源文件与测试；结果不包含密码或可用会话令牌。全组退出条件还包括真实存款闭环、取款/转账/风控/幂等、数据库核对、可复现部署及备份恢复，各成员须提交记录。

## 统计与证据规则

总数等于通过、失败和未执行之和。通过率为通过数除以已执行数，执行率为已执行数除以计划总数。独立路径记录是 JUnit 总量的子集，不再次累加。S1 实测功能与全组资金业务待测场景分开统计。所有时间以证据文件为准，测试人记 S1，实际执行由 Codex 辅助，本人尚需复核。

## 复现

在仓库根目录用 PowerShell 执行 scripts/run-exp4-tests.ps1，指定 -JavaHome、-MavenPath、-PythonPath；本机有独立缓存时再指定 -Settings 与 -MavenRepository。脚本先运行 Maven，再收集结果并执行 HTTP；原始日志保留本地，纳入仓库的 JSON 不含环境变量、完整 JVM 属性、密码或令牌。
