# 实验四 · 测试报告与部署方案

**目标**：设计测试方案，对已实现模块用**基本路径法**设计用例做组件测试，用**等价类划分法**做功能测试，
分析结果，并给出部署方案。

## 写作清单

### 1. 概述
- [ ] 测试方案：测试过程、测试方法、测试工具（JUnit / Postman / Apifox / Selenium 等）
- [ ] 测试范围与环境（被测模块、数据库版本、部署方式）
- [ ] 进入/退出准则（什么情况下开始测、什么情况算测完）

### 2. 组件测试（基本路径法）
- [ ] 画出被测方法的**控制流图**，计算环路复杂度 V(G)
- [ ] 推导独立路径，为每条路径设计用例
- [ ] **表 4-1 模块测试记录**（编号 / 路径标识 / 输入 / 期望输出 / 输出内容 / 发现问题 / 测试结果 / 测试时间 / 测试人）
  - 建议覆盖：`TransferService.transfer()` 或 `RiskEngine.check()` 这类含多重分支的方法

### 3. 功能测试（等价类划分法）
- [ ] 列出输入域的有效等价类与无效等价类
- [ ] **表 4-2 功能测试记录**（编号 / 功能名称 / 输入内容 / 期望输出 / 输出内容 / 发现问题 / 测试结果 / 测试时间 / 测试人）
  - 必测功能：存款、取款（含余额不足）、转账（含冻结账户）、超额风控拦截、重复提交幂等

### 4. 测试结论
- [ ] 强项、弱项、不符合项统计（用例总数 / 通过数 / 失败数 / 通过率）
- [ ] 遗留缺陷与风险说明

### 5. 部署方案
- [ ] 部署拓扑（与实验二的部署图一致）
- [ ] 环境要求、配置项清单（端口、数据库连接、JVM 参数）
- [ ] 部署步骤（可命令化，最好有 `deploy/README.md` 对应）
- [ ] 回滚方案与备份策略

## 用例清单

用例明细维护在 [测试用例清单.md](测试用例清单.md)，测试记录表据此填写。

## 常见扣分点

- 只有功能测试，没有基本路径法（指导书明确要求）
- 用例全是 happy path，没有一条失败用例（正常系统必然有失败路径）
- 测试记录里"输出内容"与"期望输出"抄成一样，看不出真的执行了
- 部署方案只有一句"用 Docker 部署"，没有拓扑、配置、步骤
- 测试人签名与实际提交记录对不上
