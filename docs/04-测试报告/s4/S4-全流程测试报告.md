## 4. 缺陷与发现

### DEF-S4-006（已修复）：名单 REMOVE 静默失效

- 现象：`POST /risk/lists/changes`（`op=REMOVE`）提交→审批均返回 200，但 `risk_list_entry` 中目标条目的 `enabled` 仍为 1。
- 根因：提交时每次生成**新的** `entryId`，审批时 `applyList` 对 REMOVE 执行 `DELETE ... WHERE entry_id = <本次新 entryId>`，而该 ID 从未落库，故删除 0 行且不报错。
- 连带：旧条目无法删除，下一轮同对象 UPSERT 会 INSERT 同一 `(list_type, subject_type, subject_id)`，触发唯一键 `uk_list_subject` 冲突，审批接口返回 500。
- 修复：REMOVE 改为按 `(list_type, subject_type, subject_id)` 删除；UPSERT 先按自然键查询，存在则 UPDATE（保留 `entry_id`、`rule_version+1`），不存在才 INSERT。
- 验证：F10 由 FAIL 转为 PASS；单独探针确认 REMOVE 后条目剩余数为 0。

### DEF-S4-008（已修复）：名单归属字段失真

- 现象：审批落库时 `created_by` 与 `approved_by` 都写成审批人；接口返回 `submittedBy = approvedBy`。
- 根因：`RiskListService.applyList` 的 INSERT 使用 `approver` 参数填充 `created_by`。
- 修复：插入时 `created_by` 取 `risk_change_request.submitted_by`，`approved_by` 取审批人；返回体同步回读。
- 验证：探针实测新增条目 `submittedBy=OPS-RISK`、`approvedBy=RISK-APPROVER`。

| 现象 | 说明 |
| --- | --- |
| `reason` 实际必填 | `GET /customers`、`/accounts/scoped`、`/risk/events` 未带 `reason` 返回 400，尽管声明 `required=false` |
