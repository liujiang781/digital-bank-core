## 2. 部署拓扑

单机开发/答辩拓扑：一台机器跑全部组件，只有网关对外提供 HTTP，业务服务与内部接口不直接暴露。

```
                     ┌──────────────────────────────┐
  浏览器 / Postman → │ gateway             :8085    │ 唯一对外入口
                     │ （与 S1 前端代理口径一致）    │
                     └───┬────────┬────────┬────────┘
                         │        │        │
              /api/v1/auth│  /api/v1/accounts│  /api/v1/deposits
                         ↓        ↓        ↓
                  user-service  account-service  transaction-service
                     :8081        :8082              :8083
                                                   │ /internal/v1/risk
                                                   ↓
                                              risk-service :8084
                         └────────────┬─────────────┘
                                      ↓
                             MySQL 8.0  payment_db :3306
                             Redis 7（可选，当前后端未使用）:6379
```

要点：

- `/internal/v1/**` 不经网关路由，只能由服务直连端口访问，靠内部令牌（`X-Internal-Token`）鉴权。
- 网关负责 traceId 透传（`X-Trace-Id`，1–64 位字母/数字/下划线/短横线）。
- 开发阶段允许"容器起依赖 + 本机分步起应用"，这只是依赖环境方案，不等于一键部署全部应用。

## 6. 部署步骤（干净环境）

以下命令工作目录默认为仓库根目录。PowerShell 与 Git Bash 命令不同处分别标注。

### 6.1 准备依赖环境

方式 A：本机已有 MySQL（当前采用）

```powershell
# 1) 建库与 21 张表（可重复执行，会 DROP 后重建，执行前先备份）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p < deploy\sql\schema.sql
# 2) 演示数据（幂等）
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p payment_db < deploy\sql\init-data.sql
```

> PowerShell 不支持 `<` 重定向，需在 Git Bash 中执行上述两条，或改用 `Get-Content deploy\sql\schema.sql | mysql -u root -p`。

方式 B：Docker Compose（本机未安装 Docker，未实测）

```bash
docker compose -f deploy/docker-compose.dev.yml up -d mysql
docker compose -f deploy/docker-compose.dev.yml --profile optional up -d redis
```

Compose 已把 `schema.sql`、`init-data.sql` 挂到 `/docker-entrypoint-initdb.d/`，首次启动自动执行。

### 6.2 创建服务账号与授权

root 执行一次（密码自行替换，不得提交）：

```sql
CREATE USER IF NOT EXISTS 'bank_user'@'%'          IDENTIFIED BY '<随机口令>';
CREATE USER IF NOT EXISTS 'account_service'@'%'    IDENTIFIED BY '<随机口令>';
CREATE USER IF NOT EXISTS 'transaction_service'@'%' IDENTIFIED BY '<随机口令>';
CREATE USER IF NOT EXISTS 'risk_service'@'%'       IDENTIFIED BY '<随机口令>';
```

授权范围见 `deploy/README.md` 第 4 节；实际授权结果见《验证输出-实验四.txt》。

### 6.3 演示登录口令

`init-data.sql` 已内置与 S2/S3 文档一致的演示口令，建库后可直接登录，无需额外步骤：

| 身份标识 | 用户名 | 口令 | 账户 |
|---|---|---|---|
| `UID-000001` | zhangsan | `demo123` | `ACC_S2_001`（50000.00） |
| `UID-000002` | lisi | `demo123` | `ACC_S2_002`（30000.00） |
| `OPS-ADMIN` | admin | `admin123` | 运营 |

库中只存 BCrypt（`$2a$12`）哈希。需要改口令时执行：

```bash
bash deploy/sql/set-demo-password.sh
```

脚本按提示读取口令（不回显），运行时生成 BCrypt 哈希写入三个账号。重跑 `init-data.sql` 不会覆盖已设置的口令。

### 6.4 构建

```powershell
cd backend
.\mvnw.cmd clean install
```

必须先 `install`，否则单独启动模块时解析不到父 POM 与 `common`。离线环境可加 `-o`；镜像不可用时可加 `-s .mvn\central-settings.xml`。

### 6.5 启动顺序

依赖 → 业务服务 → 网关。业务服务之间无启动顺序强依赖，但网关应最后启动，避免路由到未就绪的实例。

```powershell
# 终端 1：user-service
.\mvnw.cmd -pl user-service spring-boot:run
# 终端 2：account-service
.\mvnw.cmd -pl account-service spring-boot:run
# 终端 3：transaction-service
.\mvnw.cmd -pl transaction-service spring-boot:run
# 终端 4：risk-service
.\mvnw.cmd -pl risk-service spring-boot:run
# 终端 5：gateway（先设置端口，再启动）
$env:SERVER_PORT = "8085"
.\mvnw.cmd -pl gateway spring-boot:run
```

一次性按顺序拉起可使用 `deploy/scripts/start-all.ps1`（自动注入 `.env`、为每个服务单独指定端口、等待健康检查通过）。前四个业务服务终端不要设置 `SERVER_PORT`。

### 6.6 复现验证

```bash
python backend/scripts/smoke.py     # 五 JAR 起在 18080–18084，验证存活、四条路由、traceId、内部路径不被转发
```

| 检查项 | 命令 | 期望 |

## 8. 备份与恢复

### 8.1 备份

```powershell
$ts = Get-Date -Format "yyyyMMdd-HHmm"
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" -u root -p `
  --single-transaction --routines --triggers --default-character-set=utf8mb4 `
  payment_db > "deploy\backups\payment_db-$ts.sql"
```

- `--single-transaction`：InnoDB 一致性快照，不锁表。
- 备份文件放 `deploy/backups/`，该目录加入 `.gitignore`，不提交。
- 建议频率：每次 `schema.sql` 重建前、每次演示数据重置前、答辩当天开考前各一次。

### 8.2 恢复

```powershell
# 恢复到当前库（会覆盖同名对象，先确认已备份）
Get-Content "deploy\backups\payment_db-20261117-1015.sql" -Raw | `
  & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p payment_db
```

恢复到独立库做比对（推荐，避免影响在跑数据）：

```sql
CREATE DATABASE payment_db_restore DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

然后 `mysql -u root -p payment_db_restore < 备份.sql`，核对表数与关键行后再决定是否切回。

### 8.3 演练结果

演练分两轮执行，均真实跑通：

- `s2_exp4_test` 库：建 3 行演练表 → `mysqldump` 备份（1656 字节）→ `DROP TABLE` 模拟故障 → 从备份恢复 → 行数与内容一致（3 行）。输出见《验证输出-实验四.txt》第 5 节。
- `backup-restore.ps1 -Mode drill`（root 口令交互输入不回显）：自动建 `s4_backup_drill` 库与 3 行 → 备份 2005 字节 → `DROP TABLE` 后 `table_exists=0` → 恢复 → `rows_after=3`（alpha/beta/gamma）→ 自动删库。两轮均跑通：2026-11-17 20:48（`s4_backup_drill-20261117-2048.sql`）、2026-11-19 16:47（`s4_backup_drill-20261119-1647.sql`）。原始输出见《验证输出-实验四.txt》第 10、13 节。

`payment_db` 的全库备份需要 root 权限，按 8.1 执行即可，流程与演练完全一致。

## 11. 已知限制与风险

1. **CHECK 约束（原 8.0.13 限制，已消除）**：2026-11-19 前本机为 MySQL 8.0.13，`CHECK` 子句被解析后丢弃，`information_schema` 中 CHECK 数量为 0，金额 > 0、状态枚举等只能靠应用层校验。升级到 8.0.46 并重跑 `schema.sql` 后，CHECK 已在库中生效（合并 S3 增量后共 48 条，实测见《验证输出-实验四.txt》第 18 节）。若换机器复现，仍要求 8.0.16+。
2. **本机无 Docker**：`docker-compose.dev.yml` 方案未实测，交付的是模板，不是已验收结论。
3. **网关端口口径**：按 S1 部署方案与前端 Vite 代理默认，网关统一为 `8085`（S1 文档与前端 `GATEWAY_URL` 均指向该端口）。此前 S4 因本机 8080 被 `NI Application Web Server` 占用而临时使用 18080，自 2026-11-19 起全部口径改为 8085。
4. **工作副本基线**：本机已拉取 `main@abc6c62`（含 PR #27 认证过滤器改动）并构建成功，五服务按 8081–8084 + 网关 8085 启动，健康检查与存款冒烟均已实测通过（DEP-S4-012/013）。初轮验证基线为 `main@fb2719e`，两轮 13 条用例结果一致。若换机器复现，按第 6 节从拉代码开始执行。

6. **外网可达性**：用 `deploy/scripts/start-tunnel.ps1` 启动 cloudflared 快速隧道，得到公网 `https://*.trycloudflare.com` 地址，任意网络均可访问；地址每次重启变化，以脚本输出为准。局域网备选：当前 WLAN `192.168.58.145`（3306 与 8085 均已放行并实测连通），此记录的以太网 `10.100.172.254` 已断开失效。隧道开启期间网关暴露公网，演示口令必须改为强口令。
