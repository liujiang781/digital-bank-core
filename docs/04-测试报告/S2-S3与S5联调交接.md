# S2 S3 与 S5 联调交接

这次后端交付覆盖资金流水筛选、按原请求号找回交易、高频出账标记，以及告警处置审计。接口统一经网关调用，客户和后台使用各自的 Bearer 会话。示例的金额均为模拟人民币。

## 资金流水与分页

使用 `GET /api/v1/accounts/{accountId}/fund-entries` 查询实际资金变动。

| 查询字段 | 取值与语义 |
|---|---|
| `page`、`pageSize` | 页码从 1 开始，单页 1 至 100 条。返回 `data.items`、`total`、`page`、`pageSize`。 |
| `startTime`、`endTime` | 带时区偏移的 ISO 8601 时间，两端包含。例如 `2026-11-23T00:00:00+08:00`。用 `URLSearchParams` 编码，保留偏移量中的加号。 |
| `minAmount`、`maxAmount` | 两位小数字符串，两端包含，可单独使用。空白筛选字段从请求中省略。 |
| `businessType` | `DEPOSIT`、`WITHDRAWAL`、`INTERNAL_TRANSFER`、`EXTERNAL_TRANSFER`。 |
| `direction` | `CREDIT` 表示入账，`DEBIT` 表示出账。金额字段为正值，展示符号从资金方向确定。 |
| `tradeNo`、`reason` | 可按原交易号查账。运营或风控查询时填写原因，服务端同时核验账户授权范围并留审计。 |

同一请求的筛选条件同时生效，`total` 是筛选后的总数。结果按记账时间倒序，同一时间按内部流水编号倒序。每条流水含 `entryId`、`tradeNo`、`entryRole`、`businessType`、`direction`、`amount`、`bookBalanceAfter` 和 `occurredAt`。

S5 接入「我收到的款项」时，对本人各账户按 `direction=CREDIT` 和界面筛选条件拉取资金流水。用返回的 `total` 继续请求后续页，再合并、排序和显示全局页，按 `entryId` 去重。包含已注销账户的历史入账。跨行与行内的类型直接取 `businessType`，出入账标签取 `entryRole` 或 `direction`。

交易原单列表继续通过 `GET /api/v1/transactions` 查询，用于查看待确认、拒绝和恢复等处理状态。回单与原单详情继续使用原接口。

后台调用账户详情、余额与操作记录时，也要在查询参数中传入 `reason`。路径分别为 `/api/v1/accounts/{accountId}`、`/api/v1/accounts/{accountId}/balance` 和 `/api/v1/accounts/{accountId}/operations`。服务端记录审计，客户查本人账户时可省略该参数。

## 提交响应丢失

`GET /api/v1/transactions/by-request?businessType=EXTERNAL_TRANSFER&requestId=<UUID>` 返回本人原交易号、业务类型、状态、金额、账户号及失败原因。四种资金业务类型沿用上表定义。找不到本人原单返回 404，参数不合法返回 400。找到原单后按既有交易详情流程刷新；需要重试提交时沿用原 `requestId` 和原内容。

## 运营状态与操作

| 状态 | 建议在页面展示的含义 |
|---|---|
| `ACCEPTED` / `PROCESSING` | 已接收／处理中 |
| `UNKNOWN` | 待确认，出账资金仍可处于占用 |
| `RECOVERING` | 已有明确失败依据，资金恢复尚未完成 |
| `SUCCESS` | 已完成本地资金与流水处理 |
| `FAILED` / `REJECTED` | 失败／受理前拒绝，区分业务原因 |

使用 `data.status` 判断资金业务状态。运营待处理列表使用 `status=PENDING` 并带查询原因。对原交易显式发起 `POST /api/v1/transactions/{tradeNo}/reconcile` 或 `/recover`，请求体为 `{"reason":"操作原因","requestId":"<UUID>"}`。岗位和对象权限由服务端核验，风控查询使用只读入口。风控登记解除结论后，运营提交实际生效的全部限制编号执行解冻。

## 风控高频标记与处置

- 查询 `GET /api/v1/risk/events?result=MARK&reasonCode=HIGH_FREQUENCY&reason=复核异常`。在风险记录页将 `MARK` 显示为「可疑标记」，`HIGH_FREQUENCY` 显示为「高频出账」，拦截记录仍按 `REJECT` 展示。
- 默认同账户 60 秒内第 5 笔及后续已受理出账产生标记。每个窗口只计入该账户已受理的取款及两类转账。风控服务定时落标，页面可刷新查询，交易继续按正常资金流程处理。
- 调用 `POST /api/v1/risk/alerts/{eventId}/dispose`，请求体包含 `decision`、`basis` 和 `requestId`。结论支持 `CONFIRMED`、`FALSE_POSITIVE`、`ESCALATED`。成功响应带 `eventId` 和 `tradeNo`。同请求号同内容重放返回原处置记录，同号改内容返回 409。
- 规则列表新增 `RK-06`，类型为 `FREQUENCY_MONITOR`。界面为该类型展示启用状态和审批动作。金额字段供 `LIMIT_POLICY` 使用。规则和名单使用不同的风控账号完成申请和审批，保留账户授权范围。

## S5 页面验收

1. 用超过 100 条流水的本人账户验证入账列表翻页，再覆盖类型、金额上下限、时间边界和无结果。用其他客户登录确认账户和原请求号不可查询。
2. 正常本行转账同时核对付款出账、收款入账和两边余额。用同一请求号重放并核对原交易号与两条原流水。
3. 使用相同的测试库依次演示跨行 `UNKNOWN`、迟到成功，以及明确失败后的恢复。记录原交易号、资金占用是否释放、页面状态和流水条数。
4. 使用有范围的风控账号查看高频标记并处置，用运营账号尝试风控处置并核对 403。审批使用另一风控身份，检查申请未审批时和审批通过后的状态。
