## 二、业务边界

### 纳入范围

1. 客户注册、实名信息、登录认证；活期账户开立、账户列表、余额和状态查询。
2. 管理员冻结与解冻账户；客户办理存款、取款、本行转账和模拟跨行转账。
3. 交易流水记录与查询；对账信息作为流水查询的延伸展示，不设独立对账功能；单笔限额、日累计限额和异常交易拦截。
4. 支持上述业务所需的基础权限控制、输入校验和敏感信息脱敏。

### 排除范围

不接入人民银行支付系统、银联或真实银行接口；不进行真实资金清算；不实现利息、贷款、理财和生产级安全合规认证。跨行收款行与清算结果都由系统模拟。

## 三、业务规则决议

以下编号沿用 S2《00-需求基线与规则》，与《实验一需求规格说明书》v1.2 保持一致；早期讨论中的旧编号（原 BR-01 冻结、BR-02 金额等）已废止，引用时以本表为准。

| 编号             | 决议                                                                                | 用例与验收要点                                                                      |
| -------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| BR-01 币种与金额    | 仅模拟人民币和虚拟资金；交易金额必须大于零、最多两位小数，且不得超过可用余额。                                          | 金额无效或余额不足时拒绝出账，账户余额不变，并给出明确原因。                                               |
| BR-02 开户数量     | 每名客户最多三个未注销账户，正常与冻结账户均计入。                                                         | 达到上限拒绝再次开户。                                                                  |
| BR-03 账户状态     | 账户冻结后禁止新存款、取款、转账及接收新的行内转入；冻结前已受理交易继续确认、核对或恢复，不会永久悬挂。解冻后恢复收付资格。                    | 冻结账户提交新的收付请求时直接拒绝，余额不变，提示冻结原因。                                               |
| BR-04 余额口径     | 账面余额 B、占用 R、可用余额 A 满足 A=B-R，且 B≥0、0≤R≤B。                                          | 并发及恢复后仍满足不变式。                                                                |
| BR-05 交易限额     | 取款、本行转出和跨行转出在出账前接受风控校验。存款单笔上限建议 50,000 元；取款及两类转账共用出账单笔 10,000 元、每账户自然日累计 50,000 元，均为课堂建议参数。 | 超限时拒绝并记录拦截事件，资金不变；日累计含已成功及仍占用的出账，失败恢复后释放原日额度。单笔校验列为 P0，日累计校验列为 P1。           |
| BR-09 冻结权限     | 运营人员或风控专员可记录原因并冻结；全部有效原因解除后由运营人员解冻，风控冻结须有风险解除依据。                                  | 无依据不得解冻，操作留痕。                                                                |
| BR-11/12 幂等    | 每个交易请求带唯一请求标识；同一标识和相同内容重复提交只处理一次并返回原结果，同一标识对应不同内容时拒绝。                             | 重复点击或网络重试不能产生第二次扣款、入账或资金流水。                                                  |
| BR-13 存款入账     | 渠道明确成功后余额增加并追加入账流水；失败不入账，未知结果待确认。                                                 | 不能凭提交或超时显示已到账。                                                               |
| BR-14 出账处理     | 取款与转账受理后先占用资金及额度；明确成功后扣账并释放占用，明确失败且恢复完成后释放。                                       | 未知结果保留占用，失败不造成重复资金效果。                                                        |
| BR-15 本行转账     | 本行转账的付款扣减与收款增加必须同时成功或同时失败。                                                        | 任一账户校验失败时双方余额均不变；成功时双方流水可以用同一交易编号关联。                                         |
| BR-16/17 模拟跨行与恢复 | 跨行转账仅模拟外部清算。外部明确成功且本地处理完成后报告成功；外部明确失败且释放完成后报告失败；结果未知时保持待确认，恢复未完成时保持恢复中。           | 处理中或待确认时不可重复动用该笔资金；超时不直接退款或判成功；最终失败不会造成资金损失，状态变化和最终资金变动可追溯。                  |
| BR-19 资金流水     | 每次实际资金变动都生成可追溯的交易流水，已产生的流水不得修改或删除，需要纠错时追加冲正流水。                                    | 流水含唯一编号、账户、交易类型、金额、时间、状态和关联交易编号，可按时间、金额和类型查询；失败但未造成资金变动的请求保留处理/拦截记录，不伪造资金流水。 |
| BR-20 权限与审计    | 仅客户本人可以查看自己的账户和交易；冻结/解冻及风控拦截记录由有权限的管理员处理，重要操作记录操作者、时间、原因与结果。                      | 越权访问被拒绝；展示敏感身份信息时作必要脱敏，审计可追溯。                                                |

## 四、范围和优先级决议

优先级与现有 `BACKLOG.md` 保持一致。P0 是课程原型的必须项，P1 应完成，P2 在时间允许时完成；P1/P2 仍属于分析范围，实验一需要描述其需求和关键流程。

| 优先级 | 用户故事或交付项                                                                      | 决议                                                                        |
| --- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| P0  | US-01、US-02、US-10—US-13、US-20—US-22、US-24、US-25、US-30、US-40—US-43；EN-02、EN-03 | 开户登录、账户查询与冻结、存取款和本行转账、流水与幂等、单笔限额及对应页面；完成故事地图、用例与领域模型。存款 US-20 是后续原型的必验流程。 |
| P1  | US-03、US-04、US-23、US-31、US-33                                                 | 资料维护、客户管理、模拟跨行转账、日累计限额和拦截记录查询。对账查询作为流水查询的延伸，不增加真实清算范围。                    |
| P2  | US-32                                                                         | 高频交易可疑标记，工期不足时可保留分析说明而不实现。                                                |

本次特别校正：余额与状态查询 US-11、账户列表 US-12、冻结/解冻 US-13 均为 **P0**，不能在纪要中降为 P1。跨行转账 US-23 为 **P1**，但实验一仍需分析其活动流程。上述口径须经小组确认后再作为后续实验的验收依据。
