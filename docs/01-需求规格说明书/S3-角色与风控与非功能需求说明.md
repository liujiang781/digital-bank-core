## 1 角色

### 1.1 角色表

| 编号 | 角色 | 来源 | 职责 | 数据范围 |

## 2 风控规则

### 2.1 规则清单

| 编号 | 规则 | 对应 BR | 适用用例 | 判定条件 | 处理结果 | 优先级 |
|---|---|---|---|---|---|---|
| RK-01 | 账户状态校验 | BR-03、BR-09 | UC-TR-01—04 | 付款或收款账户为冻结、注销状态 | REJECTED，提示状态异常，余额不变 | P0 |
| RK-02 | 可用余额校验 | BR-04 | UC-TR-02—04 | A = B − R < 交易金额 | REJECTED，不产生占用 | P0 |
| RK-03 | 幂等校验 | BR-11、BR-12 | UC-TR-01—04 | 同一身份、操作类型、requestId 重复 | 返回原结果；业务内容不同则报冲突 | P0 |
| RK-04 | 单笔限额校验 | BR-05、BR-06 | UC-TR-01—04 | 存款 > 50,000；出账 > 10,000；或超过个人 L1 | REJECTED，提示限额 | P0 |
| RK-05 | 日累计限额校验 | BR-05、BR-07 | UC-TR-02—04 | 当日已成功 + 已占用 + 本笔 > min(50,000, 个人 Ld) | REJECTED，提示剩余额度 | P1 |
| RK-06 | 高频交易标记 | S3 建议 | UC-TR-02—04 | 同一账户 1 分钟内出账 ≥ 5 笔 | 标记可疑并记录，转风控专员核查，不阻断 | P2 |

### 2.2 限额口径（沿用 BR-05—07）

| 项目 | 取值 | 口径 |
|---|---|---|
| 存款单笔上限 | 50,000 元 | 仅适用于存款 |
| 出账单笔上限 | 10,000 元 | 取款、行内转账、跨行转账共用 |
| 出账日累计上限 | 50,000 元 | 每个付款账户每自然日，取款与两类转账合计 |
| 个人单笔限额 L1 | 0 < L1 ≤ 系统单笔上限 | 客户为本人付款账户设置，默认等于系统上限 |
| 个人日限额 Ld | L1 ≤ Ld ≤ 系统日累计 | 新限额不得低于当日已成功与已占用合计 |
| 自然日 | 00:00—24:00（Asia/Shanghai） | 跨午夜完成仍归原受理日，不转占新一天额度 |

### 2.3 执行约定

| 编号 | 约定 | 取值 / 要求 | 依据 |
|---|---|---|---|
| RC-01 | 币种与金额 | 仅 CNY；金额 > 0 且小数不超过两位；不计息、不计费、不允许透支 | BR-01 |
| RC-02 | 余额口径 | 账面余额 B、资金占用 R、可用余额 A，A = B − R，B ≥ 0，0 ≤ R ≤ B | BR-04 |
| RC-03 | 冻结范围 | 冻结账户禁止新存款、取款、转账及接收新的行内转入；允许查询；已受理交易继续确认与恢复 | BR-03 |
| RC-04 | 解冻条件 | 全部有效冻结原因解除；风控冻结需风控专员出具解除依据；由运营人员执行 | BR-09 |
| RC-05 | 出账资金处理 | 受理时 B 不变、R 增加；成功时 B 与 R 同减；失败释放 R 与额度 | BR-14 |
| RC-06 | 存款入账 | 渠道明确成功后才增加 B；结果未知保持待确认，不提前入账 | BR-13 |
| RC-07 | 幂等与回执 | requestId、tradeNo 贯穿全链路；重复请求与重复回执不产生第二次资金效果 | BR-11、BR-12、BR-18 |
| RC-08 | 参数配置 | 限额、时间窗、笔数阈值配置化，不硬编码 | NFR-12 |
| RC-09 | 拦截留痕 | 记录交易号、规则编号、请求号、时间、结果、操作人 | BR-20 |

### 2.4 风控结果与交易状态映射

| 风控或外部结果 | 交易状态 | 资金口径 |
|---|---|---|
| 校验与风控通过，正在处理 | PROCESSING | 出账已占用资金与额度；存款未入账 |
| 校验或风控拒绝 | REJECTED | 无资金或额度占用 |
| 外部结果未知或超时 | PENDING_CONFIRMATION | 保留原占用；存款不提前入账 |
| 明确失败且本地恢复未完成 | RECOVERING | 保留未完成的占用或恢复义务 |
| 明确失败且恢复完成 | FAILED | 占用与额度已释放，B 无本次变化 |
| 成功依据完整且本地处理完成 | SUCCESS | 入扣账正确，占用已消除 |

## 3 非功能需求

### 3.1 基线（沿用 S2 NFR-01—06）

| 编号 | 类别 | 指标 | 验证方式 |
|---|---|---|---|
| NFR-01 | 权限隔离 | 客户不能通过修改账户号、交易号、请求标识访问他人数据；运营与风控操作检查授权范围 | A/B 两客户与运营角色越权用例 |
| NFR-02 | 金额与一致性 | 始终保持 A = B − R；重复请求、重复回执、恢复重试不产生重复资金效果；可用余额与日剩余额度不被并发穿透 | 重复与并发用例 |
| NFR-03 | 可追溯 | 通过 tradeNo、requestId 串联用例输入、交易状态、资金记录、外部结果与恢复日志；不记录密码、完整令牌 | 日志抽查 |
| NFR-04 | 响应目标 | 10 名并发模拟客户，预热 1 分钟后持续 2 分钟，提交申请与查询 P95 ≤ 2 秒 | 压测 |
| NFR-05 | 超时与持续核对 | 外部调用 5 秒无明确结果返回待确认；每 10 秒查询一次；连续 3 次未知进入运营待处理清单 | 故障注入 |
| NFR-06 | 可解释反馈 | 区分已接收、处理中、待确认、成功、失败、恢复中；“已接收”不得显示为“已到账” | 界面走查 |

### 3.2 S3 补充（NFR-07—14）

| 编号 | 类别 | 指标 | 验证方式 |
|---|---|---|---|
| NFR-07 | 身份认证 | 密码加盐哈希存储；会话失效规则明确；未登录 401，越权 403 | 代码审查、接口测试 |
| NFR-08 | 输入安全 | 参数化查询、输出转义，防 SQL 注入与 XSS | 代码扫描、安全测试 |
| NFR-09 | 数据保护 | 卡号、证件号、手机号脱敏；日志不含密码与令牌 | 界面与日志核查 |
| NFR-10 | 操作审计 | 冻结、解冻、限额变更、核对、恢复记录操作者、时间、对象、原因、结果、关联号 | 日志抽查，依据 BR-20 |
| NFR-11 | 可用性 | 单服务异常不影响登录与查询；核心交易给出明确失败或待确认，不静默丢失 | 故障注入 |
| NFR-12 | 可维护 | 限额、规则参数配置化，修改无需改代码、无需重启 | 现场演示 |
| NFR-13 | 可测试 | 账户与交易核心逻辑有单元测试；覆盖存取款、转账、风控、恢复的端到端用例 | 测试报告 |
| NFR-14 | 兼容性 | Chrome / Edge 最近两个大版本，1366×768 及以上 | 手工验证 |

## 6 术语

| 术语 | 含义 |
|---|---|
| B / R / A | 账面余额、资金占用额、可用余额，A = B − R |
| requestId | 业务请求标识，幂等校验的组成部分 |
| tradeNo | 交易号，贯穿资金处理、外部请求、回执、流水与核对 |
| NORMAL / FROZEN / CLOSED | 账户正常、冻结、注销三种状态 |
| RECEIVED / REJECTED / PROCESSING / PENDING_CONFIRMATION / SUCCESS / RECOVERING / FAILED | 交易状态，完整定义见 S2《00-需求基线与规则》 |
