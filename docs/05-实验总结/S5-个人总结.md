# S5 个人总结

> 2026-11-23 由 S5 本人验收。内容基于当日真实执行记录。

我负责实验四的 S5 任务，也就是前端与联调。我先读了分工表和前三个实验的记录。我发现前端已经有登录、存款、转账等页面，还有构建产物。所以我没有照分工表里“前端只有 README”的说法写。

我重建了后端 JAR，然后启动了五个服务和网关。我写了接口端到端脚本。脚本经网关跑了 30 条用例，覆盖登录、存款、取款、本行转账、跨行转账、幂等、限额、渠道三态和越权查询。我又写了页面脚本，用无头浏览器跑了 6 条用例。我把余额、交易、流水和渠道记录做了前后核对。结果都由脚本写入证据目录。

我遇到三个问题。第一，渠道切回成功后，交易不会马上变成成功，脚本轮询 21.4 秒才看到结果。第二，前端代理端口和 README 写的不一样，我只报告，没有改文档。第三，页面连续点击会留下一个确认弹窗。我在存款页加了确认锁，然后重跑 6 条页面用例，弹窗只剩一个。

我还发现复位脚本的账户编号和当前库不一致。我把两套编号都写进脚本，然后在临时库验证通过。

我还有两件事没做。我没有测员工的运营页面和风控页面。我也没有做手工浏览器操作。这些缺口我都写进了测试记录。

这次我学会了先核对代码再写测试计划。我也看到异步收敛会让一次查询的结果不可靠。下次我会先确认环境口径，再固定测试用例。
